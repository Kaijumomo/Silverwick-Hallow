LOCAL DEVELOPMENT SAFEGUARDS
Use npm run dev:development or npm run build:development. Ordinary npm run dev
also uses Vite's development mode. The checked-in .env.development contains
only public client identifiers for the registered development app.

In development mode, or whenever VITE_FIREBASE_ENVIRONMENT=development:
- Only the exact development project, database URL, API key, app ID, auth
  domain, storage identifier, and sender ID are accepted.
- Partial or mixed configuration fails closed. A saved browser configuration
  is never used as a fallback and cannot override this build's configuration.
- The same validation runs at initFirebase before SDK initialization or cache
  reuse, covering callers that bypass normal configuration resolution.
- Even valid development configuration cannot initialize a hosted SDK client:
  an unconditional development connection gate remains in place. There is no
  environment-variable switch to authorize multiplayer testing.

The normal production build path is intentionally unchanged. These safeguards
apply to development mode/marked builds; they are not a permission boundary
against someone modifying source or deliberately building a production target.

was changed by this work. Do not use a production-mode build for testing.
